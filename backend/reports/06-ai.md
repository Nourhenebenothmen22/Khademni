## 1. AI Architecture Overview

The Intelligent Teacher Recruitment Platform employs an **Offline, High-Performance Hybrid Matching Engine** designed to parse teacher CVs and evaluate candidate suitability against job posts without external API cost latency or data leakage risks:

```
[ Application CV File (PDF/DOCX/TXT) ]
                     │
                     ▼
       [ Document Parser Service ]
       └─ Extracts raw text & structured data (document-parser.service.ts)
                     │
                     ▼
       [ AI Matching Engine Service ] (matching.service.ts)
       ├─ Phase 1: Weighted Keyword Extractor & Matcher (40% Weight)
       ├─ Phase 2: TF-IDF Vectorizer & Cosine Similarity Engine (25% Weight)
       └─ Phase 3: Rule-Based Qualification Evaluator (35% Weight)
                     │
                     ▼
       [ Application Score Synthesis ]
       ├─ Calculates Aggregated Score (0.0 - 100.0)
       ├─ Assigns Recommendation Tier (HIGHLY_RECOMMENDED, RECOMMENDED, etc.)
       └─ Stores Matching Run & Technical Metrics in DB
```

## 2. Component Breakdown

### 1. Document Parsing Subsystem (`document-parser.service.ts`)
- **Parser Implementation**: Integrates the `pdf-parse` engine (`PdfParseEngine` v1.1.1) for reliable text extraction from candidate PDF resumes ([`document-parser.service.ts`](file:///c:/full_stack%20projects/intelligent-teacher-recruitment-platform/backend/src/modules/matching/document-parser.service.ts)). Supports Word (`.docx`, `.doc`) and plain text documents. Features a robust fallback mechanism for corrupted documents.
- **Data Structuring**: Computes generic document metadata (`characterCount`, `wordCount`, `lineCount`) and extracts contact info using deterministic regex patterns.
- **Persistence**: Extracted text and structured JSON metadata are saved to `DocumentParseResult` in PostgreSQL ([schema.prisma:L249-L261](file:///c:/full_stack%20projects/intelligent-teacher-recruitment-platform/backend/prisma/schema.prisma#L249-L261)).

### 2. Semantic Embedding & Vectorizer (`semantic-embedding.service.ts` & `providers/onnx-semantic.provider.ts`)
- **Strategy Pattern Engine**: Governed by `ISemanticProvider` in [`semantic-factory.ts`](file:///c:/full_stack%20projects/intelligent-teacher-recruitment-platform/backend/src/modules/matching/semantic-factory.ts). Supports `PgVectorSemanticProvider`, `TfidfSemanticProvider`, and `OnnxSemanticProvider`.
- **Local ONNX Dense Transformer Provider (`OnnxSemanticProvider`)**: Integrates local transformer embeddings (`Xenova/all-MiniLM-L6-v2` via `@xenova/transformers`) with mean pooling, L2 normalization, and 2048-character input truncation (~350-400 words aligned with 512-token context capacity) ([`onnx-semantic.provider.ts`](file:///c:/full_stack%20projects/intelligent-teacher-recruitment-platform/backend/src/modules/matching/providers/onnx-semantic.provider.ts)). Features a 5-second initialization timeout, automatic promise reset on failure to allow subsequent retries, and graceful fallback to `TfidfSemanticProvider`.
- **Term-Frequency Vectorizer (`TfidfSemanticProvider`)**: Sparse term-frequency vectors with L2 normalization and 50+ token stop-word filtration.
- **Cosine Similarity Calculation**:

$$\text{CosineSimilarity}(V_{job}, V_{cand}) = \frac{\sum (f_{job, i} \cdot f_{cand, i})}{\|V_{job}\|_2 \cdot \|V_{cand}\|_2}$$

- **Output Metrics**: Returns exact `vectorSimilarity` ($0.0 - 1.0$), scaled `similarityScore` ($0 - 100$), provider metadata, and vector space dimensions.

### 3. Rule-Based Qualification Evaluator (`matching.service.ts`)
Evaluates JSON-structured matching rules defined by recruiters (`JobMatchingRule`):
- `EXPERIENCE`: Verifies candidate teaching experience years against required threshold.
- `DEGREE`: Validates minimum required academic degree level (e.g., Bachelor, Master, PhD).
- `CERTIFICATION`: Checks for required teaching credentials (e.g., TEFL, CELTA, State License).
- `KEYWORD`: Verifies mandatory keyword matches.

## 3. AI Model Management & Benchmark Evaluations

The `ai-models` module provides governance and evaluation tools for AI algorithms:

- **`AIMatchingModel`**: Registers model algorithm variants, version tags (e.g., `v1.2.0-tfidf-rules`), description, and hyperparameters JSON.
- **`AIMatchingModelEvaluation`**: Logs benchmark testing runs on labeled candidate datasets.
- **`AIMatchingMetric`**: Stores quantitative evaluation metrics: `ACCURACY`, `PRECISION`, `RECALL`, `F1_SCORE`, `PRECISION_AT_1`, `PRECISION_AT_5`, `NDCG_AT_5`, `MAP`, `MRR` ([schema.prisma:L71-L81](file:///c:/full_stack%20projects/intelligent-teacher-recruitment-platform/backend/prisma/schema.prisma#L71-L81)).

## 4. Vector Database & Future LLM Extensibility

- **Current Implementation**: Pure TypeScript in-memory TF-IDF vectorizer. Zero external API calls.
- **Vector DB Readiness**: PostgreSQL schema and dependencies include `pgvector` annotations in `package.json` (`keywords: ["pgvector"]`). The clean interface in `semantic-embedding.service.ts` allows dropping in Dense LLM Embeddings (e.g., OpenAI `text-embedding-3-small`, Ollama `nomic-embed-text`, or Qdrant/pgvector) without changing consuming services.
